# ADR-002: Integridad y conservación de evaluaciones vocacionales

| Campo | ADR-002 |
|---|---|
| **Título** | Registro transaccional de evaluaciones y conservación de sus reglas de cálculo |
| **Estado** | Propuesta sobre la persistencia existente en PostgreSQL, pendiente de verificar la atomicidad del registro y la identificación de versiones del cuestionario |
| **Contexto** | Nexora conserva perfiles, evaluaciones y resultados en PostgreSQL mediante SQLAlchemy, el proyecto cambia de un cuestionario histórico de 30 preguntas a uno de 20 preguntas, el driver D2 exige conservar resultados coherentes y el escenario E2 requiere evitar evaluaciones parciales ante un fallo de persistencia |
| **Decisión** | Registrar la evaluación, sus respuestas y su resultado dentro de una misma transacción, confirmar la operación únicamente si todas las escrituras tienen éxito y revertirla ante un fallo, asociar cada evaluación con la versión del cuestionario y de sus reglas de cálculo, conservar los resultados históricos sin recalcularlos de forma automática con reglas nuevas |
| **Alternativas** | (a) Confirmar cada escritura por separado: se descarta porque un fallo puede dejar respuestas sin resultado o evaluaciones incompletas, (b) recalcular todo el historial con las reglas actuales: se descarta porque modifica el significado de las evaluaciones anteriores, (c) conservar solo el resultado final: reduce el almacenamiento, pero limita la revisión de las respuestas y del cálculo |
| **Consecuencias** | A favor: mantener la coherencia de cada evaluación, permitir la revisión de sus reglas y conservar el historial, en contra: mantener versiones de cuestionarios, almacenar sus referencias y preparar migraciones para las evaluaciones existentes |
| **Trade-off** | Se acepta mayor complejidad en el modelo de datos y en las migraciones para conservar la trazabilidad y evitar resultados históricos ambiguos |
| **Vínculo** | Driver D2 y D4, escenarios E2 y E4, restricción R-08, requisitos RF-03, RF-04 y RF-05, vista C4 nivel 2: API de Nexora → PostgreSQL |
| **Verificación prevista** | Ejecutar 30 registros con un fallo inducido entre la escritura de respuestas y resultados, comprobar 0 evaluaciones parciales y 0 cambios en evaluaciones anteriores, modificar una ponderación para una versión nueva y verificar que los resultados históricos permanecen iguales |

## Tratamiento de las evaluaciones existentes

Las evaluaciones anteriores deben conservar sus respuestas y resultados originales, la versión histórica solo puede asignarse si existe evidencia suficiente sobre el cuestionario y las reglas utilizados, los registros cuyo origen no pueda determinarse deben identificarse como versión histórica no determinada.
